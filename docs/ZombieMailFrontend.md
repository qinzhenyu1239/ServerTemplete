# 僵尸项目邮件前端

客户端：D:/apk/TowerDefence。参考喵呜现有邮件模块的业务操作和当前用户资料的事件分层，不修改喵呜、服务端功能、数据库结构、统一导表Program或协议定义。

## 调用与入口

MainInterface 的“邮件”按钮 → UIMgr.ShowUI(nameof(UIMail)) → UI发布MailRequestedEvent → MailManager → MailNetwork → SessionNetwork。
Manager通过带请求标识的MailUpdatedEvent返回单次操作结果，并通过显式会话级快照事件更新未读提示、恢复状态和其他活动面板。UI不直接调用Manager业务方法或Network。
MainInterface邮件入口位于用户信息按钮下方，按钮显示未读数量。面板含滚动列表、正文／附件滚动区、刷新、单封领取、一键领取、单封删除、删除已读、关闭和确认窗口；全部预制体引用已绑定。

## 数据与操作

- PLAYER=102，七组原协议为摘要110／111、列表112／113、阅读114／115、领取116／117、一键领取118／119、删除120／121、删除已读122／123。
- 每页50封，由Manager读完所有页面；核对mailboxVersion、游标、记录数量和重复ID。分页期间版本变化，最多整体重读3次，不显示拼接的不一致列表。
- Manager持有不可变资料快照；列表在已打开期间尽量保留顺序，新邮件追加，重新打开使用服务端排序。
- 阅读展示标题、正文、发送／到期时间及附件，通知已读或奖励已领取后灰显。正文按纯文本展示，附件按道具ID和数量展示；本次没有复制喵呜的美术图标和超链接组件。
- 删除只对已读通知或附件已领取的邮件开放，单封删除、删除已读和一键领取均有界面确认。后端继续作为权限与资产变更的唯一权威。
- 领取后保存服务端返回的绝对道具数量并发布MailRewardsUpdatedEvent；不自行累加本地金币、元宝或覆盖本地存档，也不新增完整背包UI。
- 请求超时15秒，Manager只接受一个活动操作。读请求关联面板取消；领取／删除一旦接受，不因关闭面板取消，仍受账号、连接和模块生命周期约束。
- 写请求响应丢失时标记需要核对，禁止自动重发写请求。只重读邮件列表及ReqGetPlayerItems核对状态；核对成功才重新开放写操作，核对失败保留提示，允许刷新并在下个周期继续只读核对。

## 恢复与更新

MailRecoveryHandler注册到现有恢复协调器Refresh阶段，按SessionSyncOrder.Mail执行，排在PlayerProfile之后。首次鉴权和重连时刷新摘要和服务端道具快照；面板已打开则刷新完整列表。恢复期间打开面板也会补齐列表，失败向协调器传播。
Manager按服务端时间移除过期显示并只读刷新；在线每30秒轮询摘要，面板打开时轮询完整列表。当前后端没有独立邮件变化推送协议，未新增服务端消息。
注销／断线清空邮件与道具快照，连接代次和账号校验阻止迟到响应更新新会话。所有事件监听均成对注册和退订。

## 构建和验证

客户端Tools/MailVerification/Run-Verification.ps1生成隔离Unity工程。默认生成面板；-Smoke使用受控协议端点；-Smoke -RealServer同时以独立Temp部署启动本机ServerZone/Login/Game进行真实后端联调。
真实模式拒绝占用已有服务端口，不关闭用户进程。所有临时服务由finally关闭；测试账号只按zmail_前缀和确切审计名称清理，不清理其他账号。主客户端地址配置不变。
